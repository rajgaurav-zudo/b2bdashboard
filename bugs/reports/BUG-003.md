# BUG-003 — Escaped quotes stay doubled in CSV header names

- Status: Cleared
- Severity: Low
- First observed: 2026-09-21
- Last tested: 2026-09-21
- Tested revision and local changes: `7855f7c`; local changes to `api/app/ingest/reader.py` and `api/tests/test_reader.py` (the BUG-002 fix). Also reproduced at clean `7855f7c` with those changes stashed.
- Area / source locations: [`read_table`, reader.py line 108](../../api/app/ingest/reader.py); Polars 1.17.1 `pl.read_csv` header parsing.
- Run log: [2026-09-21 fix verification](../runs/2026-09-21-fix-verification.md).

## Reproduction

Prerequisites: the running API container (Polars 1.17.1); synthetic input only; no database access.

1. Run `docker compose exec -T api python -c "import polars as pl; print(pl.read_csv(b'\"say \"\"hi\"\"\",b\n1,2\n').columns)"`.
2. Observe `['say ""hi""', 'b']`.
3. For the full matrix, run `docker compose exec -T api python - < bugs/runs/2026-09-21-read-table-matrix.py`.

## Expected result

RFC 4180 escapes a quote inside a quoted field by doubling it, so the header field `"say ""hi"""` is the name `say "hi"`. Polars already unescapes data rows this way.

## Actual result and evidence

The header keeps both quote characters of each escape:

```text
['say ""hi""', 'b']
288 cases through read_table
separator failures: 0
row failures: 0
header-name failures by header: {'say "hello"': 72}
```

Every matrix case with the header `say "hello"` fails the column-name check. That is 72 of 288 cases, covering all four separators, all three line endings and both quoting modes (a quote character always forces quoting). Separators and all data rows are correct in all 288 cases.

## Impact

An export whose header contains a literal `"` loads under a column name with doubled quotes. `apply_spec` matches on substrings and tokens after `normalize_header`, so a spec that searches for the quote text itself would miss that column. Headers without quotes are unaffected. No current dataset spec was shown to depend on a quoted header name.

## Fix

`read_table` re-reads the header record with Python's `csv` module (RFC 4180) and
takes its spelling only for names where Polars kept a doubled quote and the two
agree once unescaped, so Polars' names for duplicate or blank headers are untouched.
Regression tests: `test_escaped_quotes_in_a_header_name_are_unescaped` (all four
separators) in `api/tests/test_reader.py`. Note: the bare `pl.read_csv` call in step 1
still shows the Polars behaviour; the fix is in the app's reader.
