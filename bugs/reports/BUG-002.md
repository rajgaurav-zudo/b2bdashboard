# BUG-002 — Unquoted header punctuation overrides the actual CSV delimiter

- Status: Cleared
- Severity: Medium
- First observed: 2026-09-21
- Last tested: 2026-09-21
- Tested revision and local changes: `7855f7c` plus the uncommitted fix in `api/app/ingest/reader.py` and `api/tests/test_reader.py`.
- Area / source locations: [`_sniff_separator`, reader.py line 45](../../api/app/ingest/reader.py); `read_table` passes its result to Polars at line 121.
- Run logs: [2026-09-21 Tangent pass 01](../runs/2026-09-21-tangent-01.md); [2026-09-21 fix verification](../runs/2026-09-21-fix-verification.md).

## Reproduction

Prerequisites: Python 3 only; synthetic inputs generated by standard-library `csv.writer`. No application imports or services.

1. Run `python3 bugs/runs/2026-09-21-reader-matrix.py` from the repository root.
2. The first failing case is a tab-delimited, three-column file whose header is `Last, First, Middle\tcity\tnote\n`. This is valid: commas need not be quoted in a tab-delimited field.
3. Observe exit 1 with 27 separator failures out of 288 cases.

## Expected result

The detector returns the delimiter separating the three columns: tab for the first failure, semicolon or pipe in analogous cases. Commas within a field are data.

## Actual result and evidence

The detector returns comma. The header has two commas and two actual delimiters; `max` breaks that tie in favor of comma. The implementation considers only the header, so the following data rows cannot resolve it.

```text
288 synthetic CSV cases; 27 separator failures; all record counts passed
First separator failure: (('\t', '\n', 0, 'Last, First, Middle', 1), ',')
```

The failures cover tab/semicolon/pipe separators, LF/CRLF/CR record endings, and 1/2/10 data rows, all with minimally quoted comma-heavy header text. Fully quoted headers pass. This is distinct from BUG-001's quoted-header defect; its original regression still passes.

## Impact

Valid CSV-style exports can be assigned the wrong separator before parsing. Quoting the affected header field avoids the observed helper failure. The resulting Polars frame and user-facing ingestion outcome remain unverified because Polars is unavailable; no claim of confirmed data loss is made.

## Fix reported

2026-09-21: `_sniff_separator` now ranks each candidate delimiter first by how many of the first 50 data rows contain it exactly as often as the header does, and second by its count in the header. Both counts are taken outside quotes. The last line of the 64k head is ignored because it may be cut mid-record. In the reproduction, the header's two commas tie with its two tabs, but every row carries two tabs and a different number of commas, so tab wins. Regressions added to `api/tests/test_reader.py`:

- unquoted comma-heavy headers under tab, `;` and `|`, checked through `read_table` (three named columns, two rows);
- a ragged row that does not cost the real separator its lead;
- a header with no rows, which still picks its most frequent separator.
